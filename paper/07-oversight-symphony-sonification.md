**Abstract.** Multi-agent AI systems present a musification target existing work does not address: an unbounded, changing population of autonomous agents whose meaningful state is semantic and coordinative, not physical or infrastructural. Sonification of unbounded, behaviorally-defined populations is not itself new (network-security sonification renders exactly this kind of population as alarm signatures); what is new is rendering that population as an evolving musical texture rather than a signature or alert. Prior systems music renders a fixed, small topology, a datacenter's services, a subway's lines, as sound, one instrument per source; that approach is unavailable once the source count is unbounded and grows past the three or four streams a listener can independently track. We contribute a musical grammar built for this target: rather than one voice per agent, the agent population renders as a single evolving harmonic object, seven chord voices sharing timbre and onset grid so they perceptually fuse, with a solo line and a walking bass as the two segregable exceptions. The grammar is grounded in corpus data mined from real jazz performance (the Weimar Jazz Database (Pfleiderer et al. 2017), 406 solos, 74 performers), keeping harmonic form corpus-derived and stable while telemetry drives tempo, voice thickness, and articulation, with a set of adversarial signatures, drift, collusion, a poisoned spawn, layered on as scripted musical events rather than detected from telemetry (a detector is future work); drift specifically renders as a voice's attack trailing the shared onset grid rather than a pitch deviation alone, so the signature exploits the very cue that produces the ensemble's fusion in the first place. We built a working prototype in two synchronized realizations, a Python/MIDI batch engine and a browser/Web Audio port, and measured its mapping fidelity directly: a single-agent intake phase yields four chord voices at 73 BPM, a four-agent fan-out yields six voices at 132 BPM, and at convergence tempo returns to 68 BPM while ensemble thickness does not, showing the two channels carry independent information rather than one signal twice. No voice count, tempo, or arc was authored by hand. Multi-agent AI coordination, opaque to a human watching a visual trace at machine speed, is the motivating application; whether a listener can learn to decode this grammar for that purpose is a question for future perceptual work, not a claim this paper makes.

**Keywords.** sonification, auditory display, musification, computer music, multi-agent systems, generative music, jazz, human-in-the-loop AI, AI safety.

## 1. Introduction

Rendering a running computational system as music is an established idea: giving each service in a datacenter its own instrument, or a subway line its own voice, has been done for over a decade. Multi-agent AI systems pose a version of this problem existing approaches do not cover. A planner spawns workers, workers call tools and spawn helpers, agents negotiate and hand off authority, all in parallel, and the population doing this is not fixed the way a datacenter's service list or a subway's line count is. It grows and shrinks at runtime, and what matters about it is not a physical position or a load metric but a semantic and behavioral state, whether an agent's goal has drifted, whether two agents are coordinating in a way they should not, whether one has gone silent. No existing musification target is both unbounded in population and semantically, rather than physically, defined.

This paper starts from that gap. A listener notices an ensemble going wrong, a dropped entrance, a rising tension, a sudden silence, without attending to any single voice, but auditory scene analysis (Bregman 1990) establishes the fusion/segregation mechanism behind stream tracking, and Huron's study of voice denumerability in homogeneous-timbre polyphony (Huron 1989), precisely this design's own case, measures the resulting capacity directly: listeners reliably track three or four independent voices, falling further as the voices share timbre. A grammar that gives each agent its own voice, the way Train Jazz gives each subway line its own instrument, works only while the source count stays inside that limit. Ours does not ask a listener to track one stream per agent. It renders the agent population as a single evolving harmonic object, a chord whose thickness, spelling, and stability carry the aggregate state, monitored at the object level rather than the stream level. Section 3 develops this design's central commitment, and Section 2 develops why an unbounded agent population forces it where a fixed topology does not.

Sonification of running systems is mature (Section 2); our contribution is not that idea. It is a grammar for a target that mature work does not address, the semantic and behavioral state of an unbounded agent population, grounded in real jazz performance data and built around the perceptual constraint above; a working prototype in two synchronized realizations establishing that the grammar's musical output is structurally, not arbitrarily, correlated with the telemetry driving it; and a specific application of that grammar to AI-agent coordination, where a human overseer currently has no channel for this state beyond a visual trace that provides no coverage while they are not looking at it. We treat that application as the motivating case for the grammar's design, not as a validated result: Section 5 states plainly what remains open.

## 2. Related Work and What Is New

Why this is worth building at all. A multi-agent system emits state changes in parallel across many agents at machine speed; a human overseer's visual attention is serial, foveal, and slow. Standard instrumentation does not close that gap: agent observability captures state richly but presents it through trace trees and dashboards read one region at a time, and a display that requires foveation provides no coverage while the overseer is looking elsewhere, in a meeting, reading code, away from the screen. The auditory channel is preattentive and peripheral, reaching a listener without their looking, and temporal, matching a process whose meaning is in its unfolding. That is the case for moving this problem onto sound at all; the rest of this section places the specific technique among its neighbors.

The relevant lineage is real and must be credited, since the risk here is a known technique dressed for a new occasion.

**Sonification and auditory display.** Turning data into sound for monitoring is an established discipline (Kramer et al. 1999), with a taxonomy of what counts as sonification formalized since (Hermann 2008). Gaver, Smith, and O'Shea's ARKola simulation is the field's foundational demonstration that a complex process, a simulated bottling plant with many concurrent machine states, can be monitored by ear, each state a distinct auditory icon operators learned to parse (Gaver et al. 1991). Worth engaging, not only citing: ARKola's operators tracked more state variables than Section 1's three-or-four-stream limit would suggest, which complicates a naive reading of that limit as a hard ceiling on auditory monitoring generally. The two designs are not in tension once target is distinguished from technique: ARKola's icons are individually-identified, segregated streams, the one-source-per-signal approach Section 1 argues does not scale to an unbounded population, and its operators' higher count is plausibly won by extensive training and heterogeneous, deliberately-segregating timbres, the opposite of the fusion this design builds toward. Security operations is the closest applied precedent for peripheral monitoring specifically. SoNSTAR sonifies live TCP/IP traffic so administrators can hear the signatures of port scans and denial-of-service floods (Debashi & Vickers 2018). More directly relevant, Axon et al. ran the controlled experiment this paper's future perceptual work would extend: security practitioners performed network-monitoring tasks with and without sonification added to a standard SIEM tool, and performance improved significantly with it present, in both primary and non-primary task conditions (Axon et al. 2019). Interview and survey work with SOC practitioners found they valued it specifically for peripheral monitoring, while multitasking or away from the console (Axon et al. 2018). We take three things from this: the ear is a viable, underused monitoring channel; peripheral monitoring is the benefit practitioners themselves identify; and a track record of experimental designs for testing it.

**Musification of live systems.** A body of work renders a running system as music. Giving each datacenter service its own instrument and listening to the whole as an orchestra dates back at least a decade in the distributed-systems community (Demirbas 2016), and has recently been realized at scale: Alunno and Bientinesi sonify a supercomputer's live node activity as EDM, choosing that idiom because its structure suits continuous data-driven processes and stays listenable over long durations (Alunno & Bientinesi 2026). That reasoning is close to our own argument for jazz, and we credit it as prior art for picking a musical idiom to fit the workload.

**Train Jazz, our nearest neighbor.** Wolk's Train Jazz renders live NYC subway positions as a continuously playing jazz combo, one instrument per line, a train's position along its route mapped to a note (Wolk 2026), reaching a wide public audience in 2026 and demonstrating the thing our distribution argument depends on: a running system rendered as music is something people will listen to and share. Brian Foo's Two Trains, mapping income along the 2 line to instrument density, is the earlier art-world precedent (Foo 2015).

We differ on target and grammar, and the two are linked. Train positions are physical state on a fixed topology; we render semantic, coordinative state over an unbounded, changing agent population. Most usefully: Train Jazz gives every line a distinct timbre, which works because the MTA has a fixed, modest line count. That approach is unavailable at the agent counts we care about, for the stream-segregation reasons in Section 3, and our chorale design is a direct consequence of not being able to borrow it, not an independent aesthetic preference.

**Agent observability.** A more important foil is not in sound at all. LangSmith (LangChain n.d.), Langfuse (Langfuse n.d.), Arize Phoenix (Arize AI n.d.), and the OpenTelemetry GenAI semantic conventions (OpenTelemetry Project n.d.) already capture the semantic state we care about, an agent's goal, reasoning trace, tool calls, delegation tree; the field itself argues that structural tracing cannot see semantic failure, an agent that loops or drifts off-task still returns success with normal latency (Morph 2026), and recent work pushes capture further still, toward reasoning provenance as a first-class primitive (Vispute & Kadam 2026). What these tools capture, they present as a graph for inspection, not a channel for monitoring: reading it requires navigation, panning, expanding a subtree, and a display that requires foveation provides no coverage while an overseer is looking elsewhere. We take the captured OTel span stream as our input and render it through a channel that does not require looking at all.

**The departure.** The gap is not capture but perception. Observability has largely solved capture, standardizing on an OpenTelemetry GenAI span stream; that state is then presented through the serial visual channel described above. Sonification is a perception layer over the same captured telemetry, not a competitor to observability. Where the sonification lineage above maps low-level infrastructure metrics for operations, we render already-captured semantic agent state, foregrounding coordination events, drift, collusion, a poisoned spawn, that neither infrastructure sonification nor observability tooling was built to make audible.

**The inverse, to avoid confusion.** A separate, active line uses multi-agent LLM systems to compose music, decomposing composition across leader, melody, harmony, and review agents (Deng et al. 2024; Xing et al. 2025). Those systems are agents *as musicians*: music is the output, agents are the means. We do not use agents to make music. We make music from agents' state, and the music is an instrument for watching them.

## 3. A Musical Grammar for Agent Coordination

The heart of the proposal is a grammar mapping the states an overseer cares about onto musical structure, chosen so the important states are the salient sounds. We describe the grammar as implemented; validating it fully with listeners is itself a research program (Section 5).

**Grounding in jazz.** The grammar is grounded in a corpus model mined from the Weimar Jazz Database (Pfleiderer et al. 2017), transcribed improvisations from 74 performers (Parker, Coltrane, Davis, Rollins, and seventy others), 406 solos used after filtering (Section 4 states the filtering); statistical corpus analysis of jazz harmonic practice specifically, rather than the Western common-practice repertoire corpus studies more usually target, is itself an established method (Broze & Shanahan 2013), not a technique borrowed from an unrelated context. Jazz was chosen for a principled reason: a small ensemble improvising over a shared harmonic structure in real time, adapting to each other's actions while maintaining coherence through a common grammar, is structurally analogous to autonomous agents coordinating under a shared goal. We do not press the analogy further than it goes, jazz musicians share tempo, notation, and years of mutual training that agents do not; it motivates the corpus choice, not a claim that jazz is uniquely correct here.

The corpus grounds real chord-quality distributions and root-motion transition matrices rather than arbitrary design, and it yields a testable learnability hypothesis. Listeners acquire statistical models of the idioms they are exposed to, and these models drive expectation and the perception of violation (Huron 2006; Pearce & Wiggins 2006). If that holds, a grammar built from real jazz statistics should be cheaper to learn than an arbitrary mapping, since a jazz-familiar listener already has the schema and needs only to learn what a deviation *denotes*. We state this as a hypothesis; Section 5 leaves it as future work.

**Form and dynamics: a critical separation.** The grammar's most important architectural decision is keeping two layers separate. Harmonic form, a repeating 16-bar chorus drawn from the corpus, is fixed once per session and tiled across the piece. Telemetry drives dynamics exclusively: tempo (span-start rate, clamped to 68-132 BPM), voice thickness (agent liveness), articulation density (token throughput), and anomaly signals. An earlier design drew chord changes per telemetry window, so different activity produced different roots, and the result was harmonically incoherent, indistinguishable from noise. The fix: form is not an oversight signal, it is the grammar that makes the other signals legible. Keeping it stable gives a listener a tonal anchor against which dynamics register as information.

**The ensemble: one harmonic object, not many streams.** This is the design's central perceptual commitment and a deliberate departure from the approach used elsewhere in this space. Train Jazz (Section 2) gives each subway line its own instrument, which works because a transit system has a fixed, modest line count. An agent population has no such ceiling; it grows and shrinks at runtime, and one instrument per agent, tracked individually like a flute against a cello, fails the stream-segregation constraint from Section 1: independent tracking degrades past three or four concurrent streams (Huron 1989), exactly where per-agent visual dashboards already fail too. The chorale design below is a direct consequence of that difference between an unbounded, semantically-defined population and a fixed physical topology, not an independent aesthetic preference.

Instead the agent population renders as a single harmonic object. Seven chord voices, uniform acoustic piano, each hold one tone of the current chord. Sharing a timbre, an onset grid, and voice-led motion withholds the cues that would segregate them, so they fuse into one object: a chord. The listener monitors one evolving texture, and the oversight signals are properties *of it*: thickness (agents live), spelling (coherence), articulation (throughput), and synchrony (a voice trailing the shared attack, the signature of a diverging mandate). A listener hears a choir lose its tenors without identifying who stopped singing, and by the same logic hears an ensemble stop landing together without having to localize which voice is late: synchrony is exactly the cue the fusion above depends on, so a violation of it registers at the object level by construction, not by decomposition. A pitch deviation alone would not carry this property, since fusion here is built specifically to withhold pitch-based segregation cues; a late attack is heard as the object's own transient smearing, the same way the fusion argument requires it to be.

Two further streams sit outside the chord mass, and they are segregable precisely because they violate the fusion cues that bind it. Figure 1 shows the resulting perceptual layout.

**Chorale voicing, not per-span pitch hashing.** Pitches are not assigned per span. An initial design hashed each span independently to a pitch in the current mode, producing voices in the same key that still sounded like noise, no harmonic relationship between them. The fix is chorale voicing: one shared seven-voice voicing computed per chord change and held until the next; spans re-articulate their already-assigned tone at telemetry-driven velocity and density. Pitch moves to a per-chord decision; rhythm and dynamics stay per-span and telemetry-driven, so no information channel is lost, only the uninformative hash.

**Walking bass as a telemetry channel.** A dedicated bass voice walks an independent line below the chord. Borrowing directly from jazz practice, a quiet phase uses a sparse two-beat feel and a busy phase a full four-beat walk, a real intensity device that also encodes activity directly: bass density tracks swarm density. It emerged from calibration, the jazz convention that carries the signal most naturally.

The dual role rarely conflicts, since the idiom's own logic matches the signal: a bassist plays four-feel when music intensifies, which is exactly the telemetry meaning needed. Where they would conflict, information wins and the idiom bends, since an unreliable-feeling bass teaches the listener the channel is unreliable. The bass is never gated by section or liveness; it is the ensemble's anchor and the last voice to drop, so its absence is unambiguous.

**Activity and structure.** Tempo tracks throughput. A crescendo, new voices entering, is sub-agent spawning; a diminuendo is winding down, stalling, or decommissioning.

The implementation also carries a recurring motif, restated each chorus and developed by inversion and retrograde. We are deliberately not claiming this as an oversight channel: recognizing a re-harmonized fragment inside a dense texture is a demanding perceptual task, unlike the coarse discriminations the rest of the grammar rests on, and we have no evidence a monitoring listener would catch it. It currently does musical work, making a long run cohere as a piece, which matters for the sustained-listening question in Section 6. Whether it can carry propagation information is a study question, not an asserted property.

**Coordination and its failures.** Consonance is agreement; dissonance is divergence and conflict; resolution is consensus reached. Rhythmic lock is tight coordination; drift is coordination breaking down.

**The adversarial signatures, which are the point.** A voice's attack ramping from in-sync to audibly late over the drift window, a faint flattening bend underneath, is behavior diverging from mandate, the signature of capture or injection; the lag, not the bend, is load-bearing, since it violates the same synchrony cue fusion depends on, not a pitch cue fusion is built to withhold. Unexpected unison, voices locking together that should be independent, is a candidate collusion signature. A voice going silent mid-phrase is an agent dead, killed, or gone dark. In the prototype these are scripted injections on hand-authored spans; deriving them from live telemetry is an open direction (Section 5). The goal throughout: render the anomalies an overseer must catch as the sounds a human most reliably notices, wrong notes, broken rhythm, sudden silence.

**The mapping, stated explicitly.** Table 1 splits telemetry-to-music correspondence into two tiers by implementation status. Tier 1 is computed directly from OpenTelemetry GenAI attributes in the live span stream, implemented in both realizations. Tier 2, the adversarial signatures, is *rendered* as described but has no detector yet, injected as annotations rather than inferred. This is the difference between sonifying telemetry and detecting problems, and we state it rather than blur it.

The asymmetry is worth naming: Tier 1, carrying the aggregate coordinative state this grammar renders continuously, is fully telemetry-driven; Tier 2, the adversarial semantics, is not yet. Weigh the prototype as evidence for the first claim, not the second.

**The calibration principle.** A healthy system must sound pleasant, not merely not-wrong. Dissonance and silence are reserved almost entirely for anomalies, so a listener learns one rule: wrong sound means wrong state. This ugliness budget is structural: pitches are constrained to the current mode by default, chromatic notes reserved for anomalies, and a dense swarm thickens the chord rather than overwhelming it with per-agent detail.

The budget binds on density before pitch. Since every chord voice is restricted to a chord tone, a busy swarm cannot produce dissonance by piling on; it produces a fully spelled chord re-articulated more often, and further activity is absorbed by tempo and density rather than new pitch material, keeping a loud passage loud rather than ugly. The cost is the saturation above: past the pool size, extra agents stop being separately audible, so the ugliness budget and the scaling ceiling are the same constraint from two directions, tolerable density traded for per-agent resolution. Where that trade should sit, more pool slots against more fusion-preserving thickness, is an empirical question for the scaling work in Section 5.

## 4. Prototype

We have built a working prototype realizing the Section 3 grammar. It establishes mapping fidelity, that musical output is structurally correlated with the telemetry driving it and is not an artifact of human composition. Mapping fidelity is a property of the system, not a listener: necessary, since a mapping carrying no structure could be decoded by no one, but not sufficient, and nothing here establishes that a human perceives or acts on what it carries, that is a question for the future listening work in Section 5.

**Architecture.** Two realizations share one grammar. The batch engine (Python, `caidence.py`) maps an OpenTelemetry GenAI span sequence to a MIDI timeline played through Logic Pro X. The web engine (`director.js`, `engine.js`) ports the same logic to the browser via the Web Audio API, using real recordings: Alexander Holm's Salamander Grand Piano (Holm n.d.; CC BY 3.0) and a pizzicato double bass from the University of Iowa Musical Instrument Samples (Fritts n.d.). Both share one ensemble: 9 tracks, 7 chord voices, 1 solo line, 1 walking bass. The web engine seeds a unique, never-repeating session per visitor.

All Tier 1 and Tier 2 channels are implemented in both realizations. The note-event interchange format carries a parallel continuous-deviation stream alongside discrete note events, resolved per note to a fractional-semitone pitch at the moment it is triggered, so a single shared-sampler instrument can still bend one voice while its neighbors stay in tune. Capture, collusion, and drift's onset lag render as discrete note events, no format extension needed; the drift bend and conflict signature use the continuous stream. Both realizations draw on the same anomaly rendering, which is what the supplementary audio described below exercises.

**Corpus and harmonic model.** The harmonic model was mined from the Weimar Jazz Database's beat-synchronous chord annotations (Pfleiderer et al. 2017; a separate layer from the solo melody transcriptions, which supply only the performer-style melodic interval statistics used elsewhere): 456 solos, 74 performers, 406 used after filtering out solos with no unambiguous major or minor key in the database's own key field, or fewer than four annotated chords after collapsing consecutive repeats of the same chord (a repeat is a held chord, not a transition). Chord roots are stored tonic-relative, converted to a scale degree via distance from that solo's own tonic before counting, so the matrix is a distribution over harmonic function, not absolute pitch class, and self-transitions are excluded by the same collapsing step. This yields a 12-degree chromatic root-transition matrix plus a chord-quality distribution per root. Verified: the 7-to-0 root motion (dominant to tonic) is the corpus's most frequent transition, matching textbook V-I; quality at root 2 is 70% minor-seventh and at root 7 is 83% dominant-seventh, textbook ii-V. The corpus stays load-bearing for cell selection, each candidate harmonic cell scored by its root motions' probability in the mined matrix, so progression reflects real practice rather than arbitrary design.

**Swarm simulation.** A mock pipeline (`swarm.py`), intake, a planner spawning workers, workers calling simulated tool servers, convergence, emits OTel GenAI spans whose musical form is derived from its own telemetry via a section-derivation function, not authored. We note the limit of simulation as evidence: the mock pipeline is cleaner than production telemetry, which carries irregular arrival, dropped and late spans, retries, and interleaving. Robustness under that noise is not established here and is a stated prerequisite for the live-ingestion work in Section 5.

**A structural-fidelity observation.** Running the swarm produces a measurable difference across phases. Figure 3 plots one run (seed 0). Intake, one agent live, yields four chord voices at 73 BPM. Fan-out to four concurrent agents yields six chord voices at 132 BPM. Convergence returns tempo to 68 BPM. None of voice count, tempo, or arc was written by hand; all three are computed from the span stream.

![Figure 3](figures/fig1_channels.pdf)

**Figure 3.** Telemetry in, two independent musical parameters out, for one swarm run (`swarm.py`, seed 0, 153 spans over 69.6 s; harmonic model `corpus_model_jazz.json`; regenerate with `make_figures.py --seed 0`). Panel A is the input: individual span arrivals as ticks, with the per-movement arrival rate overlaid. Panel B is tempo, which tracks span rate and returns to its opening value at convergence, 73 BPM down to 68 BPM. Panel C is ensemble thickness, which does not return: the chord stays at six voices because agents remain live even as their span rate collapses. Movement boundaries are derived from the telemetry, not authored. Every value plotted is measured from the engine's own exported note events.

The behaviour at convergence is the more informative observation, and one we did not design for. Tempo returns almost exactly to its opening value, 73 down to 68 BPM, while thickness does *not*: the chord stays at six voices rather than four, because agents remain live through convergence even as span rate collapses. The two channels move independently, exactly what the form/dynamics separation in Section 3 predicts, and a listener is not receiving one signal encoded twice. A run that merely got busier then quieter in every dimension at once would carry strictly less information.

The pattern holds across seeds 0, 1, 7, and 42: fan-out registers 132 BPM every time, the final movement falls to 68-69 BPM every time, and thickness at convergence settles at five or six voices rather than returning to its opening width. Two caveats. 132 and 68 BPM are the clamp's endpoints, so their recurrence reflects the busiest and quietest movements saturating that range, not four runs coinciding on the same rate; the informative fact is which end saturates, not the specific number. And at seed 42 the intake window catches early worker onsets and opens at seven voices rather than four, so the thin opening is characteristic of the pipeline, not guaranteed by it.

This shows distinct coordinative states produce distinct, non-arbitrary musical configurations, mapping fidelity and nothing more. It does not show a listener hears four voices versus six, can name what changed, or could do either while attending to something else. Those are questions for the listening work in Section 5.

**Key calibration discoveries.** Several decisions emerged from building and listening rather than a priori design. Voice crossing produced audible confusion and needed explicit suppression via a parallel-fifths and crossing-avoidance pass at each chord change. Bass/piano register separation was essential; overlapping registers read as conflict rather than one piece. Agent completion timing was the most consequential: inferring completion from a silence timeout left voices sounding for 1.8 to 8.2 seconds after an agent's last activity, a lagging signal on exactly the dimension the instrument exists to convey. Treating a terminal value in `gen_ai.response.finish_reasons`, the OpenTelemetry GenAI attribute for how a model call ended, as the completion signal, falling back to silence timeout only when telemetry is silent, brought that same lag down to 0.8 to 3.2 seconds, consistent with the residual being chord-boundary quantization (a voice can only leave at a chord change) rather than a detectability failure; we report these as the ranges observed during development, not a claim of statistical central tendency over a controlled sample. The lesson generalizes: where telemetry observes a transition directly, inferring it from absence is slower and less accurate. None of this was apparent in the abstract design.

**Supplementary audio.** This submission is accompanied by rendered audio examples of the grammar in each state the prototype produces, all rendered through the batch engine described above. The clean run through intake, fan-out, and convergence is real, not hand-tuned, telemetry: the mock swarm pipeline's own derived spans (Figure 3's seed-0 run). The four implemented Tier 2 signatures, drift, collusion, a poisoned spawn, and silent failure/stall, are excerpted from the hand-authored calibration trace at their known, documented injection timestamps, consistent with Section 3's statement that Tier 2 is currently scripted rather than detected; we do not claim these excerpts are real telemetry. A browser demo (`demo.html`), generating a fresh, never-repeating session on each visit, is also available.

## 5. Future Directions

The grammar is implemented and the prototype is running. What follows are the directions we consider most load-bearing, not a complete research program.

**Listener validation.** The Section 3 mapping produces musically coherent, telemetry-correlated output; whether a listener can learn to decode it, and how quickly, is untested. The corpus grounding (Sections 3-4) motivates a learnability hypothesis, that a jazz-familiar listener already has the relevant statistical schema and needs only to learn what a deviation denotes, but this paper does not test it. A controlled listening study, measuring detection and identification of the Tier 2 signatures against a real observability baseline, is the natural next step, and the one that would turn this from a systems contribution into a validated oversight tool. We regard it as future work rather than sketch its design here, since the design depends on choices, a participant population, a training protocol, a baseline, that deserve their own treatment rather than a paragraph.

**Scaling.** A hundred agents cannot each be an audible voice; the prototype pools onto a fixed count (Figure 2). Orchestral sections, hierarchical sonification summarizing a sub-swarm as one texture, or attention-directed zoom are candidate directions, each trading per-agent resolution for a higher ceiling.

**Tier 2 signal derivation.** Current adversarial signatures are scripted injections at known timestamps. Deriving them from real telemetry, drift from embedding distance over successive spans, collusion from coordination-pattern analysis across independent agents' action sequences, is what turns the system from a music generator with known-good demos into a detector that could run on live, unlabeled traffic.

**Distribution.** A hostable prototype ingesting a live OTLP stream from real deployments, rather than synthesized or replayed spans, is the remaining step toward a public instrument rather than a demo, and the more interesting evaluation environment once it exists.

## 6. Objections and Responses

**This is just sonification for monitoring.** The same technique (Section 2), aimed at a target it has not been aimed at, an unbounded population's semantic and coordinative state rather than a fixed topology's physical or infrastructural one, with a grammar (Section 3) built around that target's constraints rather than borrowed from an infrastructure-metrics context. The contribution is the target and the grammar, not the invention of sonification.

**The listener will tune it out, like every other alarm.** This is the strongest objection. "We listen to music for hours" conflates aesthetic listening, active and self-paced, with vigilance monitoring, sustained detection of infrequent signals in an unchanging stream; the vigilance decrement, a systematic decline within the first half hour of watch, is one of the most robust findings in human factors (Davies & Parasuraman 1982; Warm et al. 2008). We do not claim the grammar escapes it. We claim musical structure itself, form, harmonic motion, phrase, provides intrinsic variation that a flat alarm tone does not, which may partly mitigate the monotony driving the decrement, and that this is testable rather than assertable: a listening study measuring performance across session length is the natural test, and belongs to the future work in Section 5, not to a claim made here.

**Can a listener decode semantic meaning from music reliably enough to act on it?** Partially, and how far is an empirical question Section 5 leaves open. The design bet is on discriminations a listener makes effortlessly, a wrong note, a broken rhythm, a silence, over fine ones; the grammar claims only what it was built to carry, not what a future study will show a listener can use.

**It does not scale to thousands of agents.** Not naively, and the ceiling is lower than that: thickness saturates at the pool size (Figure 2). Above it, spawning stays audible in tempo and density but not thickness. Scaling is a named direction (Section 5), not a solved feature; the technique earns its place first in the tens-to-hundreds regime where per-agent visual dashboards already fail.

**Who is actually listening, and what do they do when they hear a problem?** We describe a channel, not an operations procedure. The overseer we have in mind is whoever already carries responsibility for a running deployment, an operator or the on-call engineer; detection is this paper's scope, and what happens after (paging a human, halting the run, escalating) is a deployment decision this grammar does not make. It is also a channel with a hearing dependency: we position it as supplementary to the visual trace it augments (Section 2), not a replacement, so a d/Deaf or hard-of-hearing overseer loses nothing they had before. Saturation thrash (Figure 2, up to 415.9 forced voice-slot reassignments per minute at fanout 32) is worth naming plainly: a voice reassigned multiple times per second should read as an unstable, rapidly-reassigning texture, not a silently-absorbed statistic, an audible symptom of exceeding the pool's design capacity. Whether it reads specifically as "too many agents" or merely "something is wrong" is untested, and belongs with Section 5's listening work.

**Simpler alternatives would do the job.** A threshold audio alert is simpler, needs no training, and is genuinely better for any failure expressible as a threshold on a known quantity, including a thinned ensemble, thickness dropping below a count; we would not replace it there. What it cannot express is a relationship between two channels with no single crossing value on either alone: Section 4's measured convergence result, tempo returning to its opening rate while thickness does not, is relational in exactly this sense, no threshold on either channel individually flags it, only their divergence does, which the two-channel texture makes audible without a listener comparing two numbers. Asynchronous review, a post-run highlight reel, forfeits continuous, peripheral coverage but is probably right for long-running deployments and complementary rather than competing. We claim the grammar covers a mode, continuous and requiring no foveation, that these alternatives do not, not that it replaces them.

**Beautiful and informative are in tension.** They are. Pleasant music may hide the signal; signal-optimized music may be unpleasant over a long listen. Navigating that tradeoff, keeping the ugliness budget (Section 3) reserved for genuine anomalies without letting a healthy system sound merely correct rather than good, is itself part of the grammar-design problem, and arguably the more interesting design question this project raises.

**Only musicians can use it.** The corpus grounding (Sections 3-4) is meant to reduce this barrier: a grammar built from real jazz statistics is closer to a schema many listeners already carry, consciously or not, from exposure to the idiom, than an arbitrary mapping would be. Whether that holds, and for whom, is a question for the listening work in Section 5; we do not resolve it here, only motivate the design choice that bears on it.

## 7. Conclusion

We have argued for a musical grammar built for a target existing musification work does not address: an unbounded, changing population of autonomous agents whose meaningful state is semantic and coordinative rather than physical. The grammar renders that population as a single evolving harmonic texture rather than one voice per agent, a design forced by the population's lack of a fixed ceiling and by the stream-segregation limit on how many independent voices a listener can track. Ensemble thickness tracks live agent count ordinally, not as an exact readout, divergence from mandate is dissonance, an agent slipping its leash is a voice falling out of sync with the ensemble's shared attack, and coordination among agents that should be acting independently is an unexpected unison. The prototype, in two synchronized realizations, establishes that this mapping carries real structure: musical output measurably, non-arbitrarily tracks the telemetry driving it, with tempo and ensemble thickness moving independently across a run's phases exactly as the form/dynamics separation predicts. It does not establish that a listener perceives or decodes that structure, and we have been careful throughout to say so rather than let the prototype's existence imply it.

Multi-agent AI coordination, illegible to a human watching a visual trace update in parallel at machine speed, is the application that motivated this grammar and the one we think makes it matter beyond a compositional exercise. Whether it can also serve that application, whether a human can learn to hear an agent system the way an experienced listener hears a choir losing its tenors, is the open question we leave to the future work in Section 5. What this paper establishes is narrower and, we think, sufficient on its own: a jazz-grounded musical grammar for an unbounded, semantically defined source population, and a working demonstration that there is real structure in the resulting signal to eventually learn to hear.

### Section 5.2 study design (parked; the prototype's first experiment if resumed)

Title: "Ear versus Screen: detecting coordination anomalies in a multi-agent AI system."

Research questions. RQ1: does sonification enable faster and/or more accurate detection of injected coordination anomalies than a state-of-practice visual dashboard? RQ2: how does any auditory advantage scale with the number of concurrent agents? RQ3: does sonification support peripheral monitoring, detection while a secondary task competes for attention?

Hypotheses. H1: sonification yields lower detection latency than the dashboard, with the gap widening as agent count rises. H2: sonification yields higher sensitivity (d-prime) for relational or gestalt anomalies (drift, collusion-unison, silence). H3: the dashboard wins on anomalies that require reading an exact value; sonification wins on relational ones. H4: under a concurrent secondary task, sonification preserves detection better than the dashboard.

Design. Within-subjects 2 (modality: sonification vs dashboard) by 3 (agent count: 8, 24, 64), modality order counterbalanced (Latin square), distinct anomaly instances per block to prevent timeline learning. Optional exploratory third modality: sonification-plus-dashboard combined. Jazz-harmony literacy (not musicianship) as a continuous moderator, measured via a validated audiation instrument plus a short jazz-specific discrimination test at intake, to answer "only musicians can use it" with a dose-response relationship rather than a musician/non-musician split.

Stimuli and apparatus. Replay real recorded agent traces (OTel GenAI span streams from actual multi-agent runs, e.g. a coding swarm and a research swarm) so base activity is ecologically valid and identical across conditions and participants. Inject a controlled anomaly set at known timestamps. Render two synchronized presentations of the same underlying trace: (a) sonification, pre-rendered in Logic Pro X with real orchestral samples so every participant hears identical high-fidelity audio and timbre quality is not a confound; (b) a strong visual baseline that is an actual observability trace/graph UI (LangSmith/Arize style) or a faithful reconstruction, so we compare against state of practice, not a straw man.

Anomaly set (balanced instances, plus no-anomaly and benign-salient distractors for false-alarm/specificity):
1. goal drift / capture (voice bends off-key);
2. collusion (unexpected unison / coordinative lock);
3. poisoned spawn (out-of-place crescendo or new voice in the wrong key);
4. silent failure / stall (voice drops out);
5. runaway loop / thrash (stuck rhythmic ostinato).

Procedure. Train the grammar to a criterion with feedback (report training time as a real cost). Primary task: detect and classify anomalies (keypress plus type). Secondary task in a subset of blocks (e.g., a low-load visual n-back) to test peripheral monitoring (H4). Manage session length for fatigue.

Measures. Primary: detection latency (onset to correct detection) and signal-detection sensitivity/criterion (d-prime, hits, misses, false alarms). Secondary: identification accuracy, NASA-TLX workload, secondary-task decrement, and subjective sustained-use realism ("could you do this for an 8-hour shift").

Analysis. Pre-register hypotheses, analysis, and exclusions. Mixed-effects models (latency via survival/Cox with censored misses; d-prime via lmer), fixed effects modality, agent count, anomaly type, jazz-harmony literacy, and interactions; random effects for participant and scenario. Report effect sizes and CIs. Pilot (N approx 6-8) to calibrate anomaly salience and training time and to power the main study; within-subjects keeps N feasible for a solo researcher (target approx 24-40).

Threats and controls. The dashboard baseline must be genuinely strong or the result is unfair; state this. Match anomaly detectability across modalities via independent raters or pilot calibration so the audio is not simply rigged more obvious. Handle order/learning by counterbalancing and distinct instances. Handle the aesthetic-quality confound by using real samples (this is why the Logic path matters for the science, not only the demo). Acknowledge the lab-versus-shift ecological gap.

Interpretation. The claim is validated if sonification shows a latency and/or sensitivity advantage that grows with agent count and survives divided attention, especially on relational anomalies. A dashboard win on value-reading anomalies is expected and honest, and refines the contribution ("auditory for relational and peripheral, visual for precise values"), which is publishable either way. This design is the single result that turns the prototype from a systems demonstration into an oversight-validation result, and it is executable by one person, if and when the pilot/participant constraints that ruled it out for now change.
